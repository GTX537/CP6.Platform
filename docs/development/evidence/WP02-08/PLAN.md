## Versioned protocol

- Namespace `CP6.Platform.EntityFramework.OutboxV2`, profile `cp6-outbox-lease-v2`, version 1; public EF-library seams `ClaimBatchV2`, `CompleteClaimV2`, `RenewClaimV2`, `QueryClaimMutationV2`, `BeginDrainV2`, `AdvanceEpochV2`, `DeleteEligibleInTransactionV1`. Shared legacy contracts stay unchanged.
- Owner-injected adapter supplies current registered tenant/Owner/queue/route/worker, current read or write authority, pre-existing Owner lock inventory, approved lease/retry/batch/publish budgets, mapping and migration/writer/cutover references. Serialized caller claims are not authority. Actual context, trusted-context object, connection, native transaction identity, provider, isolation and locks are checked.
- Add opt-in model and companion tables for RouteControl, LeaseBinding, immutable ClaimRequest/ClaimReceipt, MutationReceipt, history/audit. Original Outbox table/PK/global MessageId uniqueness/payload remain authoritative. Empty claims also persist request identity so reentry cannot claim new rows.
- PostgreSQL xmin is the actual native token. Versioned opaque codec `pg-xmin-v1:<unsigned decimal>`; EF's existing byte[] public property is explicitly converted to network-order 4-byte uint in the opt-in PG model only. No fabricated counter, root RV substitution, legacy automatic adoption or backfill. Tokens are read after the final native/Binding update; a capability forbids a second mutation of those rows in the same transaction.
- Lock protocol: caller transaction with no unproven preheld advisory locks; registered existing Owner advisory transaction locks in declared order, then persisted unique RouteControl advisory key, then root row FOR UPDATE, stable native IDs, Bindings, receipts/DLQ/audit. Verify real pg_locks and connection/xact identity. This separate profile cannot be combined with InboxV1 locks without a future Owner proof.
- Use database clock_timestamp at the final conditional native update, strictly before expiry; not transaction-start/worker time. Every mutation compares the supplied post-claim native and Binding tokens, complete tuple and root epoch/phase. Writes use caller transaction and never commit it. Only independent authoritative receipt reads after the original transaction ended can return Committed. Missing receipt is Unknown, including actual commit followed by lost acknowledgement.
- Immutable canonical input JSON retains exact request/mutation tuple. Same key+same tuple returns original result with no state write; mismatch conflicts. Historical receipt confirmation never itself grants send permission. Dispatch revalidates current claim and sufficient publish budget in a short transaction, ends transaction, then invokes publisher; transport and completion exceptions remain separate. Success/ambiguous transport plus failed confirmation is UNCERTAIN_DELIVERY, preserving exact message and mutation tuple.
- Durable Active/Draining/Blocked/Retired phases. Drain permits valid same-epoch completion but denies claim/renew. Advance requires current control version, bounded complete nonterminal inventory, no live claim, and Owner's authoritative same-root unknown-resolution/handover proof. Expired dispatches return Pending with UNCERTAIN_DELIVERY history; historical receipts survive. Root/bindings/audit change together.
- Old claim/complete/fail/requeue/retention explicitly exclude V2-owned native and related DLQ rows. Owner-installed PostgreSQL guards enforce exclusion even for old contexts without the opt-in model and concurrent cutover. Guard installation is supplied as an explicit migration asset; readiness checks actual catalog presence and mapping, plus Owner adoption evidence. Missing guards/root/model keeps V2 disabled. Runtime does not install or migrate anything.
- Exact-candidate retention rechecks current Owner policy/version, expected native token, terminal receipt, consumer/reference closure, hold/unknown/conflict, dedup/archive proof under the same root; missing evidence retains. Delete native/Binding/eligible DLQ only, keep immutable original receipt/audit/dedup identities. No Inbox evidence is deleted by the new seam.

## Recorded implementation refinements

During implementation and the single concentrated review, the original scope was refined without widening paths: immutable per-native claim rows supplement the empty-batch request header; a durable one-send-intent-per-claim record prevents request reentry from creating a replacement mutation; Owner authority row descriptors are locked FOR UPDATE before RouteControl to defeat pre-lock Serializable snapshots; readiness verifies all token/model mappings, unique indexes and unconditional full-event triggers. These changes implement the frozen original guarantees rather than new host or business responsibilities. Corresponding real-PG regressions and the review dispositions are retained with the task.
